# Soccer Duel — Desktop

Аркадный футбол один на один на маленькой закрытой площадке. Задание: [TASK.md](TASK.md). Модель: [assets/player/README.md](assets/player/README.md).

Состояние на 14 ноября 2026 года: **одиночная песочница и первая версия сетевой дуэли** (комната на двоих, авторитетный сервер). Код написан с нуля в этой папке; из старого `games/soccer-duel` ничего не перенесено.

Репозиторий игры: `https://github.com/mixermf/footduel` — эта папка является его рабочей копией (собственный `.git`), сервер Railway разворачивается из него.

## Зафиксированные решения

- **Движок:** Three.js 0.185 + Vite 5, обычный JavaScript (ES-модули), настольный браузер.
- **Будущая desktop-упаковка:** Electron поверх `vite build` (локальный `dist/`, без сети). Упаковка ещё не сделана — это этап 7.
- **Симуляция:** фиксированный шаг 120 Гц с интерполяцией изображения. При просадке время теряется, физика не ускоряется.
- **Анимация:** корпус, руки, голова и таз берутся из motion-capture клипов Mixamo, которые предоставил пользователь (см. [assets/mocap/README.md](assets/mocap/README.md)), в фазе с шагами симуляции; ноги ставятся в точки стоп из симуляции через IK. Ассеты и код Pro Evolution Soccer 6 не используются — PES остаётся только видеореференсом поведения. Набор ещё не принят пользователем.
- **Первый тестовый ПК:** AMD Ryzen 7 5800X3D, NVIDIA GeForce RTX 5070, 32 ГБ ОЗУ, Windows 11, 1920×1080 @ 120 Гц. Замер FPS на нём ещё не проводился.

## Запуск

Из корня репозитория (PowerShell):

```text
npm.cmd run dev:soccer-duel-desktop     # http://127.0.0.1:3014
npm.cmd run test:soccer-duel-desktop    # тесты симуляции
npm.cmd run build:soccer-duel-desktop   # релизная сборка без лаборатории
```

Внутри папки игры работают `npm.cmd run dev`, `test`, `build`, `build:lab` (сборка с лабораторией), `preview`, `server` (сервер матчей на порту 8787).

## Игра по сети

Матч один на один до 7 голов. Один игрок создаёт комнату и получает код из пяти символов и ссылку-приглашение (`?room=КОД`); второй входит по коду или по ссылке. Когда оба в комнате и загрузились — отсчёт 3 секунды и игра. После гола мяч вводит пропустивший. После матча — реванш по согласию обоих.

**Как устроена синхронизация.** Сервер авторитетен: он считает ту же симуляцию 120 Гц, что и клиент (`src/sim`), и 30 раз в секунду рассылает полное состояние матча. Клиент шлёт ввод по шагам, своего игрока двигает сразу, не дожидаясь ответа, а каждое состояние сервера восстанавливает целиком и доигрывает поверх него ещё не подтверждённый ввод. Соперник между состояниями продолжает движение с последним известным вводом. Расхождение показанного и исправленного положения гасится плавно, без рывка. Точного совпадения вычислений между машинами схема не требует.

**Соперник на экране.** Своего игрока и мяч клиент считает сам, без задержки. Соперника угадать на время пинга вперёд нельзя, поэтому он рисуется по подтверждённым состояниям сервера с плавной интерполяцией и отставанием около 70 мс плюс половина пинга. При пинге до 60–80 мс это незаметно; при 150–200 мс мяч после удара соперника появляется уже в полёте, и это лечится только близким сервером. Замер пинга: `node scripts/net-ping.mjs https://адрес-сервера`. В отладочной сборке задержку можно имитировать параметрами `?lag=мс&jitter=мс`.

**Свёрнутое окно и простои.** Когда окно скрыто или кадры перестали идти, клиент просит сервер не слать ему состояния, а его игрок на сервере стоит. При возврате клиент отбрасывает всё накопленное и берёт одно последнее состояние сервера: пропущенное время не доигрывается и не проматывается. То же происходит после любого простоя кадров дольше 0,3 с.

**Обрыв связи.** В матче место держится 30 секунд: игра ставится на паузу, клиент переподключается сам и возвращается по токену. Если игрок не вернулся — комната закрывается. Скрытая вкладка и меню отпускают ввод, матч при этом не останавливается.

### Проверить локально

```text
npm.cmd run build      # собрать клиент в dist/
npm.cmd run server     # http://localhost:8787 — игра и сервер матчей вместе
node scripts/net-bot.mjs КОД   # второй игрок-бот для проверки в одиночку
```

В режиме разработки (`npm.cmd run dev`, порт 3014) клиент ищет сервер матчей на `ws://localhost:8787`. Адрес можно задать параметром `?server=wss://…` или переменной сборки `VITE_SERVER_URL`.

### Сервер Railway

Один сервис Railway отдаёт и саму игру, и WebSocket матчей — отдельный хостинг для клиента не нужен. Настройки лежат в `railway.json`; в панели Railway нужно:

1. **Источник:** подключить GitHub-репозиторий `mixermf/footduel`, ветка `main`. Корневая папка — корень репозитория. Каждый `git push` в `main` запускает новую сборку.
2. **Networking → Generate Domain:** выдать публичный домен. Порт указывать не нужно: сервер слушает `PORT`, который задаёт Railway. Этот домен и есть адрес игры; WebSocket работает на нём же по пути `/ws`.
3. **Реплики: ровно одна.** Комнаты хранятся в памяти процесса; при двух репликах игроки одной комнаты попадут на разные процессы.
4. **Serverless / App Sleeping: выключить.** Засыпание сервиса обрывает матчи.
5. **Регион:** ближайший к игрокам (для Европы и России — EU West, Амстердам). Задержка до сервера — главное, что влияет на ощущение: 14 ноября 2026 года пинг до `footduel-production.up.railway.app` был 190 мс, то есть сервис стоял в далёком регионе.
6. Сборка и запуск определяются сами: `npm ci` → `npm run build` → `npm start`; проверка состояния — `GET /health`. Нужен Node.js 20 или новее (указано в `package.json`).

Переменные окружения, все необязательные:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ALLOWED_ORIGINS` | список адресов через запятую, с которых разрешён WebSocket (например домен Railway); пусто — разрешены все | пусто |
| `MAX_ROOMS` | предел одновременных комнат | 200 |
| `PORT` | порт; Railway задаёт сам | 8787 |

Каждое развёртывание перезапускает процесс и закрывает идущие матчи (игроки видят сообщение о перезапуске). Расход трафика — около 55 КБ/с на игрока во время матча.

## Управление

| Действие | Клавиатура | Геймпад Xbox / PlayStation |
|---|---|---|
| Бег; с мячом в окне удара — направление мяча | стрелки | левый стик, крестовина |
| Удар: заряд, удар при отпускании (с мячом и без) | D | X / □ |
| Ускорение | W | RB / R1 |
| С мячом: навес «парашютом» | A | B / ○ |
| С мячом: суперудар (при полной шкале) | Q | LB / L1 |
| С мячом: чеканка; в чеканке — подбить выше | Пробел | Y / △ |
| В чеканке: удар с лёта; навес; суперудар | D; A; Q | X / □; B / ○; LB / L1 |
| Удары по высокому мячу: сбоку в полёте, через себя, в прыжке | D (держать) + Пробел | X / □ + Y / △ |
| Без мяча: подкат | A | B / ○ |
| Без мяча: прыжок; вместе с подкатом — подкат в прыжке | Пробел; Пробел + A | Y / △; Y + B |
| Без мяча: защитная стойка и приём — телом и ближайшей ногой (удерживать) | S | LT / L2; нога — LB / L1 |
| Рывок в стойке | S + направление + Пробел | LT + стик + Y / △ |
| Точный приём; удержание — близкий контроль | E | A / × ; RT / R2 |
| Контроль и разворот к воротам | X | LT / L2 |
| Пауза | Esc | Menu / Options |
| Вернуть мяч; тренировочная подача; щит вместо ворот | R; F; G | меню паузы |

«С мячом» — мяч под контролем на покрытии, в чеканке, только что подброшен или находится в воздухе рядом с игроком (после приёма, отскока, навесной передачи: ближе 1,6 м либо подлетает в пределах полусекунды). Низкий мяч (ниже 0,75 м) дальше 0,9 м и любой мяч после прыжка — уже «без мяча»: по нему идёт подкат. Подсказка внизу экрана показывает текущий набор действий.

**Чеканка.** Пробел при владении подбрасывает мяч и сразу начинает серию: стопы по очереди подбивают мяч к точке перед игроком, с мячом можно медленно идти. Удар, навес и суперудар во время чеканки идут с лёта. Пробел в серии подбивает мяч высоко — под удар головой или через себя. Ускорение, стойка или ушедший мяч серию прекращают: не достал — мяч падает сам.

**Навес.** Работает и по лежащему мячу, и по мячу в воздухе у игрока — тогда он бьётся с лёта, без ударов в полёте и через себя. Мяч уходит круто вверх с обратным вращением и опускается почти отвесно — так перебрасывают соперника. Заряд задаёт дальность точки приземления (3,5–16 м), прицел «от ворот / к воротам» — крутизну дуги, «вверх / вниз» — сторону. Потолок коробки — 8 м.

**Суперудар.** Шкала заполняется за 22 с и быстрее — от подбивов в чеканке, приёмов и подкатов. При полной шкале Q бьёт без заряда со скоростью 30 м/с и малым разбросом; шкала обнуляется.

**Подкат.** Скольжение по направлению стрелок (без направления — к мячу, если он ближе 4 м): ведущая стопа выбивает мяч по ходу. В прыжке подкат продолжается в воздухе и достаёт мяч на весу; прыжок из подката ниже обычного. После подката игрок 0,26 с встаёт, следующий подкат доступен почти сразу.

**Стойка и приём.** S без мяча включает защитную стойку (лицом к мячу, приставной шаг, мягкий приём телом) и одновременно приём ногой. Пока S удержана, игрок следит за мячом: если мяч пройдёт в пределах метра от корпуса и не выше 0,7 м, ближайшая нога выходит ему навстречу, гасит его и оставляет перед игроком.

**Удары по высокому мячу — только из прыжка.** Удар сбоку в полёте, удар через себя и удар в прыжке выполняются, только если игрок сам прыгнул: держит удар (D) и жмёт прыжок (Пробел), либо уже находится в прыжке и нажимает удар. Если удар зажат и мяч уже идёт высоко, по нажатию прыжка игрок не взлетает сразу — толчок происходит в расчётный момент, под удар. Один удар без прыжка такие мячи не берёт: игрок ждёт, пока мяч опустится до обычного удара с лёта. Прежние условия (игрок выпрыгивает сам, хватает одной кнопки удара) возвращает `kick.jumpKicks: false` в `src/sim/profile.js`; в лаборатории (F1) это кнопка «Высокий мяч: только из прыжка».

**Удар сбоку в полёте.** Игрок лицом к воротам, удар зажат, мяч идёт высоко (от 1,45 м над полем в момент встречи): вместо прыжка вверх на уровень мяча он отталкивается (до 0,6–0,7 м), заваливает корпус вбок от бьющей ноги и бьёт на взлёте ногой, поднятой выше таза. Бьёт нога с той стороны, где мяч. После контакта нога по инерции идёт дальше через корпус и тянет тело за собой: игрок проворачивается винтом грудью вниз почти на пол-оборота, бьющая нога остаётся вытянутой позади, и он приходит на вторую ногу в низкую стойку с рукой у покрытия. Игрок не падает, но до конца посадки (0,55 с) не управляется и оказывается развёрнутым. Если на такой удар не хватает времени (нужно не меньше 0,3 с до встречи), остаётся прежний удар в прыжке.

**Удар через себя.** Игрок стоит спиной к атакуемым воротам, мяч в воздухе рядом и достаточно высоко (примерно от 1,7 м над полем): по удару он не разворачивается, а выпрыгивает, заваливается назад и бьёт через голову «ножницами» — свободная нога идёт вверх первой, на проносе бьющей уходит вниз. После удара игрок падает на спину, а если летел к мячу боком — набок, лежит и встаёт: около секунды он не управляется. Мяч ниже этой высоты бьётся обычным ударом с разворотом.

**Низовой мяч в ноги.** Если игрок повёрнут к мячу и ничего не нажимает, мяч до 9 м/с он останавливает подошвой, более быстрый принимает на щёчку — мяч отскакивает рядом. Спиной к мячу остаётся обычный отскок от тела.

**Защитная стойка.** Пока кнопка удержана и мяча у игрока нет, он встаёт ниже и шире, всегда развёрнут лицом к мячу и двигается приставным шагом (2,7 м/с, резкий старт и остановка). Мяч, попавший в стопу, бедро, грудь или голову, гасится и опускается перед игроком — в зону следующего касания; если ничего не нажимать, игрок сам делает шаг за ним. Точный приём по `E` в стойке по-прежнему даёт лучшее гашение. Прыжок с направлением в стойке — рывок в сторону примерно на 1,7 м с паузой 0,4 с до следующего; без направления остаётся обычный прыжок. С мячом стойка не включается. Удар из стойки начинается как обычно.

Во время удара направления управляют прицелом: вверх/вниз по экрану — сторона ворот, к воротам — ниже, от ворот — выше. Около 0,1 с после контакта вертикальное направление добавляет подкрутку, затем удерживаемое направление снова двигает игрока.

## Площадка

- **Ворота стоят в поле и уходят за коробку:** рама — на линии ворот в 0,8 м перед торцевым бортом, в борту проём, сетка тянется от рамы ещё на 0,9 м за пределы коробки (глубина ворот 1,7 м). Стойки и перекладина — круглые (радиус 6 см): мяч отскакивает по нормали к поверхности, от внутренней стороны штанги уходит в ворота, от внешней — в поле.
- **Сетка — настоящая преграда с обеих сторон.** Изнутри гасит забитый мяч, и он остаётся в воротах. Снаружи не пускает мяч в ворота сбоку и сверху; с верхней сетки мяч скатывается обратно в поле через перекладину. За линию ворот сбоку от рамы можно зайти, в сами ворота игрок не заходит.
- **Сетка прогибается от мяча:** удар даёт толчок полотну в точке попадания, лежащий мяч оно облегает. Это только изображение, на физику не влияет.
- **Коробка прозрачная:** выше бортов — тонированные панели с каркасом (высота возврата мяча 5 м видна по верхней раме; ближней к камере верхней балки нет, чтобы она не пересекала кадр). Борта остались цветными; ближний к камере борт полупрозрачный, иначе при низкой камере он закрывал бы ближний край поля.
- **Камера** опущена: угол к горизонту около 36° вместо 49°, обе линии ворот по-прежнему в кадре.

## Лаборатория

Доступна в dev-режиме и в `build:lab`, в релизную сборку не входит. `F1` — панель: сценарии (клавиши 1–7), замедление, пауза `P` и шаг `O`, ракурсы спереди/сбоку/близко, кости, точки стоп симуляции, диагностика, ползунки профиля, повтор записи ввода с последнего сброса, выгрузка журнала. Параметр `?autopause=0` отключает паузу по потере фокуса для автоматических прогонов.

## Что реализовано

- Этап 0: загрузка модели (масштаб до 1,85 м из фактических границ, оси по стопам, подошва на y = 0), фиксированный шаг, ввод с клавиатуры и геймпада, стабильная камера с обеими линиями ворот.
- Этап 1: мяч с вращением, сопротивлением и эффектом Магнуса, борта, сетка-ограждение высотой 5 м, стойки и перекладина отдельными коллайдерами, гол один раз за розыгрыш; мотор с разгоном, торможением и разворотами.
- Первая итерация этапов 2–4: ведение реальными касаниями (между касаниями мяч свободен), внеочередная подработка при поворотах, остановка мяча, удар с зарядом, прицелом, погрешностью по seed и окном подкрутки, приём стопой/бедром/грудью по таймингу, игра головой в прыжке, подброс, воллей, тренировочные подачи.
- Развороты с мячом: срезка на 50–120°, убирание подошвой назад при развороте круче 120° (мяч уходит мимо опорной ноги), остановка подошвой с шагом за мяч; корпус доворачивается плавно, опорная стопа пивотирует на носке.
- Процедурная поза: перенос веса на опорную ногу, подседание и наклон в разгон, торможение и вираж, инерция рук и корпуса, перекат стопы с пятки на носок, расслабленные кисти, взгляд за мячом, работа корпуса и рук в ударе.
- Цикл бега на единой фазе: стопы строго чередуются, шаги левой и правой равны по времени. Ориентиры взяты из биомеханики бега: частота шагов около 2,7–3,3 Гц, доля опоры в цикле 0,3–0,4 при 3–3,5 м/с (полёт около 0,1 с на шаг), на малой скорости полёта нет; с мячом шаги короче и чаще. Это подгонка по опубликованным числам, а не по покадровому разбору видео.
- Удар в касание по мячу, который движется сам (летит, катится на игрока, отскочил от борта): по нажатию удара прогнозируется точка встречи той же физикой, что и сам мяч; игрок выходит в неё, заранее заносит ногу и бьёт в расчётный момент. Заряд — сколько успели удержать до контакта, встречная скорость мяча добавляет силы. Мяч на весу бьётся с лёта; если стоя не достать — игрок выпрыгивает сам, ручной прыжок тоже работает. Недостижимый мяч импульса не получает.
- Песочница держит мяч в движении: после гола и после остановки на чужой половине идёт новая подача с чередованием высот; `G` ставит щит вместо правых ворот, и мяч всегда возвращается.
- Поверх motion capture добавлено аркадное усиление, чтобы движение читалось с игровой камеры: захлёст голени и длинный толчок назад, перекат опорной стопы с пятки на носок, скручивание корпуса навстречу тазу, мах рук в противоход ногам, размах рук и разворот корпуса в ударе, мах руками в прыжке.
- Удар по летящему мячу: игрок встаёт на такое расстояние от точки встречи, чтобы нога била почти выпрямленной; замах длится около 0,2 с с отведением ноги назад и в сторону; в проносе стопа сначала выходит на высоту мяча и идёт в расчётную точку встречи, а не тянется за мячом; длина «таз — голеностоп» держится в анатомических пределах. Мяч выше 0,8 м от опоры бьётся в прыжке.
- Команды песочницы (вернуть мяч, подача, щит) идут через кадр ввода и попадают в журнал: повтор записи остаётся точным. Изменения ползунков профиля в журнал не пишутся.
- Дуэль в симуляции: два игрока с одинаковыми правилами, счёт, матч до 7 голов, ввод мяча пропустившим, повторный ввод замершего мяча, сохранение и восстановление полного состояния.
- Игра по сети: комнаты по коду и ссылке, загрузка и готовность, отсчёт, авторитетный сервер, предсказание на клиенте, пауза и возврат при обрыве, реванш, главное меню. Соперник — в красной форме.
- Чеканка, удар через себя, автоматическая остановка низового мяча и приём на щёчку.
- Опорная нога больше не остаётся позади корпуса при ударе с хода и после него: стопа переставляется подшагом (раньше отставала до 1,8 м).
- Правки по разбору записи игры (15 ноября 2026): проводка удара низкая и короткая вместо прямой ноги на уровне пояса; руки в ударе без «самолёта»; в беге локти согнуты и работают попеременно, мах ноги без зависания прямой ноги позади; прыжок с прямым корпусом; удар через себя с наклоном назад и возвратом до приземления; обычное касание не дальше 0,66 м от корпуса (без шпагата); стопы не проходят сквозь борта; после подброса мяч остаётся у ног, игрок подстраивается под него.
- Защитная стойка без мяча: корпус к мячу, приставной шаг, широкая постановка стоп, рывок в сторону, мягкий приём телом с переходом к контролю, отдельная поза (ниже, руки в стороны).
- Пауза по Esc, потере фокуса и отключению геймпада; удержанные до паузы кнопки не срабатывают при возврате. Громкость, вибрация и тряска сохраняются.

## Что не сделано

- Набор анимаций раздела 10 и приёмка ощущения пользователем. Текущие позы процедурные; приём и игра головой считаются по капсуле тела с жестом поверх, а не по поверхности стопы или груди.
- Финты и суперудар (кнопки назначены, действия нет), музыка, интерфейс переназначения клавиш (проверка конфликтов и сохранение раскладки в коде есть).
- Локальная дуэль на одном компьютере, бот для одиночных матчей (есть только тестовый сетевой бот), desktop-упаковка.
- Сеть: проверка на реальном сервере Railway и с настоящей задержкой между двумя людьми; подбор соперника без кода; зеркальный вид для игрока справа (сейчас он играет справа налево); управление экранами лобби с геймпада ограничено подтверждением и выходом; звуки отскоков мяча берутся из предсказания и могут изредка не совпасть с итогом сервера.
- Замер 60 FPS на тестовом ПК, проверка на 30/60/120/144 Гц, живой плейтест на физическом геймпаде, сравнение с референсом.

## Проверки
